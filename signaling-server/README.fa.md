# سرور سیگنالینگ NATProxy

سرور سبک HTTP + UDP برای هماهنگی اتصالات نظیر-به-نظیر NATProxy. این سرور تبادل SDP offer/answer، کشف سرور با امتیازدهی سازگاری NAT و یک رله UDP غیرشفاف برای NAT متقارن را مدیریت می‌کند. بدون وابستگی خارجی — یک باینری استاتیک Go، فقط حافظه موقت.

## شروع سریع

```bash
cd signaling-server
go build -o signaling-server .
./signaling-server -addr :8080
```

این دستور هم سیگنالینگ و هم کشف سرور را روی پورت 8080 و رله UDP را روی پورت 3478 راه‌اندازی می‌کند.

### پورت‌های پیش‌فرض

| سرویس      | آدرس پیش‌فرض  | توضیحات                       |
|------------|---------------|-------------------------------|
| سیگنالینگ  | `:5601`       | تبادل SDP offer/answer        |
| کشف        | `:5602`       | لیست و مرور سرورها            |
| رله UDP    | `:3478`       | رله پشتیبان عبور از NAT       |

## فلگ‌های خط فرمان

| فلگ               | پیش‌فرض    | توضیحات                                                    |
|--------------------|----------|----------------------------------------------------------------|
| `-addr`            | *(ندارد)* | آدرس شنود برای هر دو سیگنالینگ و کشف (جایگزین دو مورد زیر) |
| `-signaling-addr`  | `:5601`  | آدرس شنود سیگنالینگ (خالی برای غیرفعال‌سازی)                |
| `-discovery-addr`  | `:5602`  | آدرس شنود کشف (خالی برای غیرفعال‌سازی)                      |
| `-relay`           | `:3478`  | آدرس شنود رله UDP (خالی برای غیرفعال‌سازی)                  |

وقتی `-addr` تنظیم شود، هر دو `-signaling-addr` و `-discovery-addr` را برای سازگاری با نسخه‌های قبلی بازنویسی می‌کند.

**مثال‌ها:**

```bash
# حالت ترکیبی — همه چیز روی یک پورت
./signaling-server -addr :8080

# حالت جداگانه — سیگنالینگ و کشف روی پورت‌های مختلف
./signaling-server -signaling-addr :5601 -discovery-addr :5602

# غیرفعال‌سازی رله UDP
./signaling-server -addr :8080 -relay ""
```

## مرجع API

تمام بدنه‌های درخواست/پاسخ JSON هستند. محدودیت حجم بدنه **16 کیلوبایت** است.

### نقاط پایانی جلسه (Session)

جلسات SDP offer و answer را برای راه‌اندازی اتصال نظیر ذخیره می‌کنند.

#### `POST /session/{id}/offer`

ذخیره SDP offer نظیر A.

- **بدنه:** آبجکت JSON (مثلاً `{"sdp": "...", "candidates": [...]}`)
- **پاسخ:** `200 OK` — `ok`
- اگر جلسه وجود نداشته باشد، آن را ایجاد می‌کند.
- هرگونه مشترک SSE که این جلسه را دنبال می‌کند مطلع می‌شود.

#### `GET /session/{id}/offer`

دریافت SDP offer نظیر A.

- **پاسخ:** `200 OK` — بدنه JSON همانطور که ذخیره شده
- **خطا:** `404 Not Found` — جلسه وجود ندارد یا offer هنوز ارسال نشده

#### `POST /session/{id}/answer`

ذخیره SDP answer نظیر B.

- **بدنه:** آبجکت JSON
- **پاسخ:** `200 OK` — `ok`
- یک SDP خالی (`{"sdp":""}`) اسلات answer را پاک می‌کند (برای مذاکره مجدد).
- هرگونه مشترک SSE که منتظر answer هستند مطلع می‌شوند.

#### `GET /session/{id}/answer`

دریافت SDP answer نظیر B.

- **پاسخ:** `200 OK` — بدنه JSON همانطور که ذخیره شده
- **خطا:** `404 Not Found` — جلسه وجود ندارد یا answer هنوز ارسال نشده

#### `GET /session/{id}/offer/stream`

استریم SSE برای بروزرسانی‌های offer. باز می‌ماند و هر offer جدید را هنگام رسیدن ارسال می‌کند.

- **Content-Type:** `text/event-stream`
- **فرمت رویداد:** `event: offer\ndata: <json>\n\n`
- اگر offer فعلی وجود داشته باشد، بلافاصله ارسال می‌شود.
- هر 90 ثانیه کامنت `: keepalive` ارسال می‌شود.
- تا قطع اتصال کلاینت باز می‌ماند.

#### `GET /session/{id}/answer/stream`

استریم SSE برای answer. یک بار تحویل داده و بسته می‌شود.

- **Content-Type:** `text/event-stream`
- **فرمت رویداد:** `event: answer\ndata: <json>\n\n`
- اگر answer از قبل موجود باشد، بلافاصله ارسال شده و بسته می‌شود.
- در غیر این صورت منتظر ارسال answer می‌ماند، تحویل داده و سپس بسته می‌شود.
- هر 90 ثانیه در حین انتظار کامنت `: keepalive` ارسال می‌شود.

### نقاط پایانی کشف (Discovery)

کشف به سرورها اجازه ثبت‌نام و به کلاینت‌ها اجازه مرور سرورهای موجود را می‌دهد.

#### `POST /discovery/register`

ثبت یک سرور در لیست.

**بدنه درخواست:**

```json
{
  "name": "my-server",
  "room": "home",
  "code": "<base64-connection-code>",
  "method": "holepunch",
  "transport": "webrtc",
  "protocol": "vless",
  "nat_mapping": "endpoint_independent",
  "nat_filtering": "address_dependent"
}
```

- `name` — اجباری، حداکثر 50 کاراکتر
- `code` — اجباری (کد اتصالی که کلاینت‌ها استفاده خواهند کرد)
- سایر فیلدها متاداده اختیاری هستند
- **حذف تکراری:** اگر لیستی با همان `name` وجود داشته باشد، جایگزین می‌شود (برای مدیریت ری‌استارت اپلیکیشن)
- **پاسخ:** `201 Created` — `{"id": "<hex-uuid>"}`
- لیست بروز شده به تمام مشترکان SSE کشف ارسال می‌شود

#### `DELETE /discovery/{id}`

حذف یک سرور از لیست.

- **پاسخ:** `200 OK` — `ok`
- **خطا:** `404 Not Found` — لیست وجود ندارد

#### `POST /discovery/{id}/heartbeat`

تازه‌سازی heartbeat لیست برای جلوگیری از انقضا.

- **پاسخ:** `200 OK` — `ok`
- **خطا:** `404 Not Found` — لیست وجود ندارد (منقضی شده یا هرگز ثبت نشده)

#### `GET /discovery/servers`

لیست سرورهای فعال.

**پارامترهای کوئری:**

| پارامتر         | توضیحات                                     |
|-----------------|---------------------------------------------|
| `room`          | فیلتر بر اساس نام اتاق (خالی = همه اتاق‌ها) |
| `nat_mapping`   | نوع مپینگ NAT کلاینت (برای مرتب‌سازی)       |
| `nat_filtering` | نوع فیلترینگ NAT کلاینت (برای مرتب‌سازی)    |

- **پاسخ:** `200 OK` — آرایه JSON از لیست سرورها
- وقتی `nat_mapping` ارائه شود، نتایج بر اساس امتیاز سازگاری NAT مرتب می‌شوند (بهترین اول)

**مثال پاسخ:**

```json
[
  {
    "id": "a1b2c3...",
    "name": "my-server",
    "room": "home",
    "code": "<base64>",
    "method": "holepunch",
    "transport": "webrtc",
    "protocol": "vless",
    "nat_mapping": "endpoint_independent",
    "nat_filtering": "address_dependent"
  }
]
```

#### `GET /discovery/stream`

استریم SSE بروزرسانی‌های لیست سرورها. هر زمان که لیستی اضافه، حذف یا منقضی شود، لیست کامل سرورها ارسال می‌شود.

**پارامترهای کوئری:**

| پارامتر   | توضیحات                                     |
|-----------|---------------------------------------------|
| `room`    | فیلتر بر اساس نام اتاق (خالی = همه اتاق‌ها) |

- **Content-Type:** `text/event-stream`
- **فرمت رویداد:** `event: servers\ndata: <json-array>\n\n`
- لیست کامل فعلی بلافاصله هنگام اتصال ارسال می‌شود.
- هر 30 ثانیه کامنت `: keepalive` ارسال می‌شود.

### سلامت (Health)

#### `GET /health`

- **پاسخ:** `200 OK` — `ok`

## رله UDP

رله برای جفت‌های NAT متقارن که hole punching در آنها شکست می‌خورد، پشتیبان عبور از NAT را فراهم می‌کند. بسته‌های UDP غیرشفاف را بین دو نظیر ارسال می‌کند — هرگز محتوا را رمزگشایی یا بازرسی نمی‌کند.

### پروتکل ثبت‌نام

نظیرها با ارسال یک بسته UDP **21 بایتی** به رله ثبت‌نام می‌کنند:

```
[0xDEADBEEF (4 بایت)][SHA256(sessionID)[:16] (16 بایت)][role (1 بایت)]
```

| آفست | اندازه | فیلد                                    |
|------|--------|-----------------------------------------|
| 0    | 4      | بایت‌های جادویی: `0xDE 0xAD 0xBE 0xEF`  |
| 4    | 16     | 16 بایت اول هش SHA-256 شناسه جلسه      |
| 20   | 1      | نقش: `0x00` = سرور، `0x01` = کلاینت    |

- ثبت‌نام fire-and-forget است (پاسخی ارسال نمی‌شود).
- ثبت‌نام‌های بعدی از همان نقش، آدرس نظیر را بروز می‌کنند.

### ارسال داده

هر بسته UDP که دقیقاً 21 بایت با پیشوند جادویی نباشد، به عنوان داده در نظر گرفته می‌شود:

- بسته‌های نظیر سرور به آخرین آدرس شناخته نظیر کلاینت ارسال می‌شوند.
- بسته‌های نظیر کلاینت به آخرین آدرس شناخته نظیر سرور ارسال می‌شوند.
- مسیریابی بر اساس آدرس مبدأ — رله `addr → (session, role)` را هنگام ثبت‌نام نگاشت می‌کند.

## امتیازدهی سازگاری NAT

وقتی کلاینت‌ها نوع NAT خود را از طریق پارامترهای کوئری ارائه دهند، سرور نتایج کشف را بر اساس امتیاز سازگاری مرتب می‌کند. امتیازدهی بر اساس انواع رفتار NAT در RFC 5780 است.

### ماتریس امتیاز

امتیازات جفت مپینگ (بالاتر = شانس بهتر hole punching):

| سرور ↓ \ کلاینت → | EI  | AD  | APD |
|--------------------|-----|-----|-----|
| **EI**             | 100 | 70  | 40  |
| **AD**             | 70  | 30  | 15  |
| **APD**            | 40  | 15  | 5   |

امتیازات جفت فیلترینگ:

| سرور ↓ \ کلاینت → | EI  | AD  | APD |
|--------------------|-----|-----|-----|
| **EI**             | 100 | 80  | 50  |
| **AD**             | 80  | 40  | 20  |
| **APD**            | 50  | 20  | 10  |

**مخفف انواع NAT:**
- **EI** — مستقل از نقطه پایانی (بازترین، بهترین برای P2P)
- **AD** — وابسته به آدرس
- **APD** — وابسته به آدرس و پورت (NAT متقارن، سخت‌ترین برای P2P)

### فرمول امتیاز ترکیبی

```
score = (mapping_pair_score * 70 + filtering_pair_score * 30) / 100
```

رفتار مپینگ وزن بیشتری دارد زیرا تأثیر بیشتری بر موفقیت hole-punching دارد. انواع NAT ناشناخته امتیاز خنثی 50 دریافت می‌کنند.

## انقضا و پاکسازی

| منبع               | TTL / انقضا                       |
|---------------------|-----------------------------------|
| جلسات              | 5 دقیقه از آخرین فعالیت          |
| لیست‌های کشف       | 90 ثانیه از آخرین heartbeat       |
| جلسات رله          | 5 دقیقه از آخرین بسته            |
| فاصله پاکسازی      | هر 1 دقیقه                       |

حلقه پاکسازی همچنین مشترکان SSE قطع‌شده را جمع‌آوری می‌کند.

## استقرار (Deployment)

### باینری واحد

```bash
go build -o signaling-server .
```

یک باینری استاتیک بدون وابستگی زمان اجرا تولید می‌کند. در هر جایی که باینری‌های Go اجرا می‌شوند قابل استقرار است.

### پلتفرم‌های ابری

این سرور روی Fly.io، Railway، Render یا هر VPS به خوبی کار می‌کند. نیازمندی‌ها:

- **پورت TCP** برای HTTP سیگنالینگ + کشف
- **پورت UDP 3478** برای رله (در صورت فعال بودن)

### پروکسی معکوس

هنگام قرار گرفتن پشت nginx یا Cloudflare، بافرینگ پاسخ را برای نقاط پایانی SSE غیرفعال کنید:

```nginx
location /session/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header X-Accel-Buffering no;
    proxy_buffering off;
    proxy_cache off;
}

location /discovery/ {
    proxy_pass http://127.0.0.1:8080;
    proxy_set_header X-Accel-Buffering no;
    proxy_buffering off;
    proxy_cache off;
}
```

### فایروال

پورت‌های زیر را باز کنید:

| پورت       | پروتکل  | سرویس                     |
|------------|----------|----------------------------|
| 5601       | TCP      | سیگنالینگ (یا سفارشی)     |
| 5602       | TCP      | کشف (یا سفارشی)           |
| 3478       | UDP      | رله                        |

## نکات امنیتی

این یک سرور **اثبات مفهوم (PoC)** است:

- **بدون احراز هویت** — هر کلاینتی می‌تواند جلسه ایجاد کند و سرور ثبت کند
- **فقط حافظه موقت** — تمام وضعیت با ری‌استارت از بین می‌رود، لایه ذخیره‌سازی دائمی ندارد
- **محدودیت 16 کیلوبایت بدنه** — از بارهای بزرگ جلوگیری می‌کند (SDP offer/answer معمولاً هر کدام حدود 4 کیلوبایت هستند)
- **جلسات موقت** — انقضای 5 دقیقه‌ای پنجره سوءاستفاده را محدود می‌کند
- **رله غیرشفاف** — رله هرگز محتوای بسته را رمزگشایی نمی‌کند، فقط بایت‌ها را ارسال می‌کند
- **مقیاس‌پذیری** — مناسب برای حدود 100-500 جلسه همزمان؛ برای تولید، احراز هویت، محدودسازی نرخ و ذخیره‌سازی دائمی اضافه کنید
